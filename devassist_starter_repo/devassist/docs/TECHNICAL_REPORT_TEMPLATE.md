## Abstract

DevAssist is a retrieval-augmented developer troubleshooting system that searches a focused Stack Overflow question-and-answer corpus, applies two-stage retrieval and generates a source-grounded response. The system combines dense semantic search with BM25 through Reciprocal Rank Fusion, reranks the top 20 chunks with a cross-encoder and supplies the best 5 passages to a low-temperature LLM. Source IDs and links are generated from retrieved metadata rather than model output. On a 25-query test set, the final configuration achieved TODO Recall@5, TODO Precision@5 and TODO MRR; manually judged faithfulness averaged TODO/2. The application also declines queries whose evidence falls below a calibrated relevance threshold.

## 1. Problem and objectives

Stack Overflow contains useful fixes, but a developer must search several threads and assess answer quality. General chat models can provide unsupported output. The objectives were therefore: (1) retrieve relevant posts across semantic descriptions and exact technical strings, (2) improve candidate ordering, (3) generate only from retrieved evidence, (4) expose verifiable citations, and (5) evaluate retrieval and generation separately.

## 2. Dataset and ethics

The corpus was downloaded through Stack Exchange API 2.3 on 2026-10-05. It contains 196 questions and 392 selected positive-score answers across Python, Pandas, NumPy, Docker and TensorFlow. The sample retained the 40 highest-voted questions requested per tag and at most two accepted/high-score answers per question. Some questions carry overlapping tags, so counts are not additive.

Raw question and answer records were stored separately and joined on `answers.question_id = questions.question_id`. Metadata includes question ID, answer ID, tags, scores, authors and canonical links. Stack Overflow user contributions remain under the applicable CC BY-SA license; the application displays links and IDs for attribution.

**Limitations:** a top-vote sample overrepresents common and older issues. It does not support FastAPI, PyTorch or Kubernetes. Those topics form negative tests for the insufficient-information path.

## 3. Preprocessing and chunking

HTML markup and entities were removed with BeautifulSoup while `<pre>`/`<code>` text was preserved in code fences. Non-positive-score answers were excluded. A document concatenates title, question and answer because the question text supports matching while the answer contains the solution.

Chunks are measured with the embedding tokenizer, not character count. The baseline uses 220 tokens with 30-token overlap, below MiniLM's 256-token maximum. Paragraph and code boundaries are preferred, every chunk repeats its title and metadata, and stable IDs follow `answer_id × 1000 + chunk_index`.

## 4. Embeddings and vector storage

The baseline embedding model is `sentence-transformers/all-MiniLM-L6-v2` (384 dimensions, 256-token maximum). It was selected for CPU speed, no per-request API dependency and a small persistent index. Document and query vectors are normalized identically.

Qdrant local mode stores one point per chunk, including vector, chunk text and citation/filter metadata. Cosine distance matches the normalized embedding setup. Stable IDs make ingestion repeatable, and local persistence makes UI startup independent of ingestion.

## 5. Retrieval and fusion

Dense retrieval captures meaning but can miss exact error names, flags and versions. BM25 captures exact terms but misses paraphrases. DevAssist executes both over the same chunk IDs. A custom tokenizer preserves technical symbols. RRF merges ranks:

`RRF(d) = Σ 1 / (60 + rank_i(d))`

Raw dense and BM25 scores are not added because their scales differ. The fused list is limited to 20 candidates, with no more than two chunks per question to improve diversity.

## 6. Reranking

`cross-encoder/ms-marco-MiniLM-L-6-v2` jointly scores each query-candidate pair. This is more precise than the bi-encoder but too expensive for the entire corpus; it is therefore applied only to 20 candidates. The best 5 chunks enter the LLM prompt. The maximum reranker score is checked against threshold TODO, chosen by comparing TODO answerable and TODO unanswerable validation queries.

## 7. Grounded generation and source integrity

The configured LLM was TODO exact provider/model. Temperature was 0.1. The prompt includes explicit system rules, five labeled context blocks and the raw developer question. The response structure requires a likely cause, numbered fixes, verification instructions and inline `[n]` citations. It forbids outside knowledge and permits refusal.

The source list is not generated by the LLM. Code validates each `[n]`, maps it to the corresponding retrieved chunk and creates de-duplicated Stack Overflow question/answer URLs from metadata. When the relevance gate fails, no answer sources are claimed.

## 8. Evaluation methodology

The test set contains 25 natural-language queries: 22 answerable and 3 unsupported. Each answerable query has manually identified relevant question IDs. Retrieval is evaluated at unique question-ID level with Recall@5, Precision@5 and Mean Reciprocal Rank. Generation is independently scored by both team members from 0–2 for faithfulness, answer relevance and context relevance; disagreements are discussed but both original scores are retained.

## 10. Reliability, security and reproducibility

Configuration and secrets are environment variables. `.env` is excluded and `.env.example` contains placeholders. The application validates empty input, caps query length, retries transient LLM failures, surfaces useful messages and logs per-stage latency in the UI trace. Tests cover cleaning, metric de-duplication and citation validation. A Dockerfile and GitHub Actions test workflow support reproducibility.

## 11. Limitations

The corpus is small and English-only. High-vote sampling can hide niche errors. MiniLM's context limit forces small chunks, and the MS MARCO reranker is not specialized for Stack Overflow. Reranker logits are not probabilities. Manual generation scoring has limited sample size. A remote LLM introduces network and cost risk.

## 12. Future work

Evaluate BGE embeddings and longer chunk configurations; add query rewriting and metadata routing; deploy Qdrant server mode behind FastAPI; add caching and structured traces; index official documentation; and allow a bounded agent to select Stack Overflow, documentation or code-analysis tools while preserving source-grounding.
